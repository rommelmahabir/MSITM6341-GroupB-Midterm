| 1 | TotalCharges | Stored as text; 11 values were blank spaces, so `isnull()` reported 0 missing | Strip spaces, set the 11 blanks to 0, convert to float | All 11 blanks belong to customers with tenure 0, who have not been billed yet, so their total charges are 0. | 2 | All columns | Checked for duplicates while customerID was present: 7,043 rows, 7,043 unique IDs, 0 exact duplicates | Removed nothing | Every row is a different customer. Ignoring the ID, 22 rows look identical, but they are different customers with the same details, so they stay. |

| 4 | Churn (target) | Stored as "Yes"/"No" text; models need numbers | Mapped Yes to 1, No to 0 | Standard binary target for classification. Churn rate is 26.5%, so the classes are imbalanced. |
| 5 | 15 text feature columns | Models cannot read text categories such as "Month-to-month" | One-hot encoded with `pd.get_dummies(drop_first=True)` | Gives each category its own 0/1 column without implying an order. Dropping one category per column avoids duplicate information (the dummy variable trap). Result: 30 feature columns. |
| 6 | All rows | Need a fair test of how the models handle unseen customers | 80/20 train/test split, `stratify=y`, `random_state=42` | Stratifying keeps the churn rate at 26.5% in both sets. The fixed seed means both models use the identical split, so their scores are comparable. |
| 7 | tenure, MonthlyCharges, TotalCharges | Very different ranges (0–72 vs. up to about 8,700) | Standardized with `StandardScaler`, fit on the training set only | Puts the columns on a similar scale for Logistic Regression. Fitting on train only prevents test data leaking into training. Random Forest is unaffected by scale. |
| 8 | Model 1 | Need a simple, interpretable baseline classifier | `LogisticRegression(max_iter=1000)` trained on the shared `get_model_data()` split | Its coefficients show which features push churn up or down. `max_iter=1000` lets the solver finish without a warning. |
| 9 | Class imbalance (26.5% churn) | The default model caught only 55.9% of churners (recall 0.559) | Compared default vs `class_weight="balanced"`, suggested by Rajendra in his PR #3 review | Balanced raised recall to 0.783 and F1 from 0.605 to 0.614, while accuracy fell from 0.806 to 0.738. Missing a customer who leaves costs more than a false alarm, so recall and F1 matter more than accuracy here. |
| 10 | Evaluation metrics | Accuracy alone is misleading when 73.5% of customers stay | Report accuracy, precision, recall and F1 for the churn class, plus a confusion matrix | A model predicting "No churn" for everyone would score 73.5% accuracy but catch zero churners. Precision, recall and F1 expose that. |
| 11 | Model 2 | Need a second algorithm that can capture non-linear patterns | `RandomForestClassifier(n_estimators=100, random_state=42)` on the same `get_model_data()` split | Trees capture interactions between features that Logistic Regression can't. Feature importances show what the model relied on. |
| 12 | Class weights in Random Forest | `class_weight="balanced"` barely changed recall (0.503 to 0.492) | Kept balanced weights, and tuned tree depth instead | Unlimited-depth trees grow until every leaf is pure, so class weights have little to act on. Limiting depth lets the weighting work. |
| 13 | Hyperparameter tuning | Default settings caught only half of churners | `GridSearchCV`: 12 combinations, 5-fold cross-validation on the training set only, scored on F1 | Best: max_depth=10, min_samples_leaf=1, n_estimators=200 (CV F1 0.636). Test recall rose to 0.725 and F1 to 0.616. The test set was never used for tuning. |
| 14 | Final model choice | Which model to recommend | Compared Logistic Regression (balanced) with Random Forest (tuned) on the same test set | F1 is nearly tied (0.614 vs 0.616). Logistic Regression catches more churners (recall 0.783 vs 0.725), is simpler, and shows direction of effect, so it's recommended. Both agree on the top drivers: tenure, contract type, Fiber optic. |
